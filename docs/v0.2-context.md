## Adaptive sampling: where samples come from

BASELINE costs no radio time beyond what the app already does. The ring logs HR every 5 min and
stress/HRV every 30 min by itself; an evaluation runs after every completed ring sync (foreground
`SyncProgress("done")` and the 30-minute background `RingSyncWorker`, which is the periodic check)
and after every spot measurement the monitor takes. Detection latency is therefore the background
sync period (15–30 min, longer if MagicOS defers the job).

Only a trigger (rest AND HR ≥ 100 or ≥ 20 above the 3 h resting median, or stress ≥ 70, or
HRV ≤ 0.7 × median of the last 6 resting values) starts `MonitorService` with type
`connectedDevice`: it holds the link and runs WATCH (HR + stress now, HR re-check every 4 min,
10 min timeout) and ESCALATED (HR every minute, HRV + stress every 3 min, no SpO₂; exit after 3 min
below HR < 90 / < median + 10, stress < 55, no HRV drop; cap 20 min, cooldown 30/60 min, daily
budget 90 min default, off in detected sleep, stop below 20 % ring battery). Spot readings are
stored as normal measurements with `sourceRaw = "adaptive_spot"` and excluded from the baselines.

Rest uses the ring's 15-minute activity buckets (any overlapping bucket counts in full, so it can
only under-report rest) or, while the link is held, the ring's live cumulative step count.

Sleep = last sleep record reaching to now, or Bedtime/DND tracking active, or 23:00–07:00 with no
steps for 30 min. A trigger while asleep is logged as `suppressed_asleep` (at most one log row per
30 min), never escalated.

Every transition, and every suppressed trigger, is a row in `adaptive_transitions` with the
inputs it saw (`valuesJson`) and is pushed to ring-hub.

**Background start rule.** Android 12+ refuses to start a foreground service from the background
unless the app is exempt from battery optimisation. The episode is then closed as `fgs_denied`.
On MagicOS: Settings → Battery → app launch → PulseLoop → manage manually, all three on.

**Background persistence fix.** `RingSyncWorker` in a cold process (app killed) used to publish the
ring's history on a bus nobody persisted. It now starts `BackgroundPersistence` when
`AppServices` does not exist; `AppServices` takes over on creation (`BackgroundPersistence.handOffTo`:
stop the background subscriber and start the app's own in the same step, subscribing synchronously,
so the `replay = 0` bus never has a moment with nobody listening).

## Labels ("Cosa stai facendo?")

Normal notification (never full-screen) at the start of an escalation, or when a stress trigger was
suppressed. Six one-tap buttons in the expanded view, the context-suggested one starred and also
offered as the first action ("✓ Traffico"), "Altro…" with free text (RemoteInput). Suggestion:
IN_VEHICLE or speed ≥ 4 m/s → Traffico; running/cycling or gym zone → Sport; work zone on weekday
hours → Riunione in the first 15 min after a full/half hour, else Lavoro. Max one per 30 min, none
23:00–07:00, times out after 30 min, never repeated.

## Diary

Optional and **off by default** (opt-in, also after upgrading; a stored choice is kept), one
notification per day at the time the user picks (default 21:30): exact alarm when
`USE_EXACT_ALARM`/`SCHEDULE_EXACT_ALARM` allows it, otherwise a WorkManager one-shot. Two delivery
modes: *Apri automaticamente* (full-screen intent → `DiaryQuickActivity` over the lock screen;
heads-up while in use; needs `canUseFullScreenIntent()` on Android 14+) and *Solo notifica* (the
three chips "Caffè dopo le 15", "Alcol", "Pasto tardi" as action buttons). Default: the first when
the permission is there. Untouched fields stay null (= unknown). Sport and screens-in-bed are
derived (Activity Recognition + workouts, UsageStats before sleep onset) and shown as hints; the
full form, morning 2-tap check and history are in Settings → Diario.

## Phone context

All opt-in from Settings → Contesto. Screen time: UsageStatsManager screen events folded into
hourly rows (needs Usage Access). Location: FusedLocationProvider `BALANCED_POWER_ACCURACY` (Play
Services) or the platform network provider, every 2 min moving / 15 min still / 5 min unknown,
raw points synced only to ring-hub, which detects stays and places. Activity Recognition
Transition API (STILL, WALKING, RUNNING, ON_BICYCLE, IN_VEHICLE) gates the location interval.
Zones (Casa/Lavoro/Palestra/custom) are set on an osmdroid map (OpenStreetMap tiles, no key) and
take precedence over auto places; places detected by the server can be promoted with one tap, in
the app or in the dashboard (pulled back on the next sync). The zone editor states under the map
that tiles come from OpenStreetMap's servers, which can infer the area being viewed.

## Sync acknowledgement

A stream's watermark moves only when ring-hub's reply lists it in `counts` with at least the rows
sent. A v0.1 server drops the v0.2 lists (`extra="ignore"`), so those watermarks stay put and the
Server ring-hub screen shows "Server non aggiornato: alcuni dati in attesa"; the rows go again once
the server is updated. Each v0.2 stream is independent: a 4xx on one is logged and skipped for that
pass (watermark kept, "Dati rifiutati dal server: …" in the status) without stopping the others.
The zones and places pulls are independent too.

## Known gaps against the spec (not implemented in v0.2)

- Labels: no `answeredAt` field (the time the user answered, as opposed to the episode time), and
  no "silence for N hours" option for the prompts.
- Diary *Solo notifica* mode offers the three chips only; there is no mood chip in the
  notification (mood is set from the full form or the quick screen).
